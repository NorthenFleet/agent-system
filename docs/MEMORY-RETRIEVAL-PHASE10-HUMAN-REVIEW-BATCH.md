# 记忆检索第十阶段：人工标注作业批次

## 目标

把可信候选池组织成可持续执行、可追踪进度的人工审核作业。系统负责选择样本、平衡来源、安排顺序和提出安全反例候选；审核结论仍由管理员逐条确认。

本阶段不批量勾选审核项、不自动改写标签、不自动激活用例、不自动运行评测，也不自动切换线上检索策略。

## 批次模型

新增 `memory_retrieval_eval_batches`，持久化：

- 批次名称、目标数量和创建人；
- 固定的用例 ID 列表，避免审核过程中样本集合漂移；
- 审核顺序、来源、问法类型和安全反例建议；
- 创建时间和当前作业状态。

批次进度从用例的实时状态计算，不复制或覆盖用例标签。

## 平衡选择策略

选择器按权威来源轮询，每轮依次选择：

1. 标准问法；
2. 自然问法；
3. 简短问法；
4. 上下文问法；
5. 边界问法。

因此会先覆盖全部权威来源，再增加同一来源的问法多样性。已归档用例不会进入新批次。

创建进行中的批次时采用幂等行为：如果当前用户已有 `in_review` 批次，返回原批次，不创建另一套相互竞争的审核集合。

## API

```http
POST /api/v3/context/evaluations/retrieval/batches
GET  /api/v3/context/evaluations/retrieval/batches/latest
```

创建接口默认目标为 30 条，最多 100 条。候选不足时明确失败，不会静默降低验收标准。

## 安全反例建议

边界问法可获得最多 3 个其他权威来源作为禁止来源建议。建议仅用于减少人工查找成本：

- 不自动写入用例；
- 工作台明确标记“仍需人工核对”；
- 审核者点击后只填入编辑表单；
- 仍需完成来源标签核验和二次确认才能激活。

## 工作台

新增“人工审核批次”区域，显示：

- 已激活数量与30条目标；
- 已覆盖权威来源；
- 已激活安全反例数量；
- 剩余数量和问法类型分布；
- “审核下一条”入口。

审核下一条会打开第一个未处理用例的证据弹窗，继续沿用第九阶段的原文证据、置信度、审核清单、来源快照和审计轨迹。

## 完成标准

- 批次30条用例均经人工核验并激活；
- 7个权威来源均有激活用例；
- 至少有1条经人工核验的安全反例；
- 来源快照无漂移；
- 运行 `memory-retrieval-eval.v3`；
- 数据集哈希与最新评测一致；
- 线上切流门禁仍只给建议，不自动切流。
