# 记忆检索第十一阶段：AI 辅助审核提案

## 目标

在第十阶段的 30 条人工审核批次上增加 AI 辅助改写和安全负例建议，降低人工标注成本，同时保持“机器提案、人工裁决、正式标签”三层隔离。

本阶段不把 AI 输出视为真实标签，不自动勾选审核项，不自动保存用例，不自动设置审核置信度，不自动激活用例，也不触发离线评测或线上切流。

## 数据边界

AI 提案只写入批次 `review_plan[].proposal`，字段包括：

- 建议的真实业务问法；
- 建议的禁止来源；
- 提案理由；
- 提案人和生成时间；
- `pending_human_review` 状态；
- 可复核的提案哈希。

正式评测用例仍保存在 `memory_retrieval_eval_cases`。写入提案前后，导入脚本会比较用例的问法、状态、版本和审核勾选；任何非预期变化都会使操作失败。

## 校验规则

服务端拒绝以下提案：

1. 不属于当前批次的用例；
2. 重复用例 ID；
3. 空问法或与当前问法完全相同的“伪改写”；
4. 不属于当前用户权威记忆集的禁止来源；
5. 同时被标为期望来源和禁止来源的冲突标签；
6. 缺少提案理由的结果。

单次最多提交 100 条，接口仅管理员可访问。

## API 与可重复制品

```http
PUT /api/v3/context/evaluations/retrieval/batches/{batch_id}/proposals
```

首批提案固化在：

- `backend/evals/memory_retrieval_review_proposals_v1.json`
- `backend/scripts/apply_memory_review_proposals.py`

导入脚本要求制品精确覆盖当前批次的 30 个唯一用例 ID，批次不匹配或覆盖不完整时立即退出。

## 提案设计

30 条提案覆盖：

- 7 条标准问法：检验权威记忆中的核心判断；
- 7 条自然问法：模拟真实用户的口语表达和追问；
- 7 条简短问法：检验低词项输入下的语义召回；
- 7 条上下文问法：加入实施、排障或任务闭环语境；
- 2 条边界问法：检验角色限制与信息权威性边界。

两条边界问法附带安全负例候选，每条 3 个无关但真实存在的权威来源。它们仍须审核者逐条确认，不能直接成为禁止标签。

## 人工审核交互

工作台批次区显示 `AI提案 30 / 30`。打开“审核下一条”后：

1. 先查看权威来源原文；
2. 查看 AI 改写、提案理由和 `PENDING` 标记；
3. 点击“应用到表单（不保存）”只会填充本地表单；
4. 人工修改问法和标签；
5. 人工核对用户、项目、智能体作用域；
6. 人工完成三项审核清单并选择中或高置信度；
7. 再通过二次确认保存和激活。

应用提案不会调用更新接口，也不会把任何审核清单改为已完成。

## 下一阶段

由管理员逐条进行真实人工裁决。每条用例需独立核对证据、问法、作用域、期望/禁止来源与置信度后才能激活。完成 30 条后再运行 `memory-retrieval-eval.v3`，检查 Recall@K、MRR、Forbidden Hit、来源覆盖和数据集哈希；评测通过仍只生成切流建议，不自动切换线上策略。
