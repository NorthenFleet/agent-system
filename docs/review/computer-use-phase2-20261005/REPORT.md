## 本阶段发现并修正

1. 取消任务后顶部错误显示“任务正在推进”。终态现在优先显示“任务已取消”，保留未解决副作用提示；无步骤的失败任务也有明确失败提示。
2. 全员状态把非当前任务的“等待反馈”当作执行中，把已完成/取消任务的擎天柱显示为统筹中。状态投影现区分等待、阻塞与执行；多任务数量改为“关联”，避免将暂停任务称为并行执行。选中任务的参与者展示该任务所属项目，避免拼接其他任务的项目名。

源文件：backend/services/command_center_service.py；frontend-v2/src/utils/commandCenterLifecycle.ts；frontend-v2/src/views/CommandCenter.vue。新增回归位于 backend/tests/test_computer_use_regressions.py 与 frontend-v2/src/test/commandCenterLifecycle.spec.ts。

## 边界

- 故障回归通过临时数据库和租约过期模拟，不等于真实运行中杀 worker 或断网演练。
- 现有运行策略仍为 pilot/shadow，不能据此宣布严格证据门禁已全面通过。
- 上一阶段 B/C 的历史冻结合同和补偿记录未改动。
- 本阶段新增两个交付轮次和一个取消轮次；不能将它们表述为三个同版本连续成功交付。

- E：救护车写作、通天晓独立审核；F：李奥纳多写作、爵士独立审核。四份文件均实际存在；下载副本 SHA-256 与交付原件一致，详见 artifact-verification.json。

- 确认全系统执行中任务/步骤为 0 后重载本地 API 与 worker。恢复后页面显示 2/2 在线、0 个过期租约、活跃执行 0，E/F 完成、G 取消状态保留。
- 前端正式构建通过，git diff --check 通过；构建仍有大包提示，后端仍有 6 条弃用提示，不影响本轮测试通过。
- 浏览器下载事件接口未稳定返回，早期简报点击也未立即找到下载副本；通过重新单独下载并核对实际文件完成验证。不能只凭点击成功宣布下载完成。

## 尚未关闭的问题与下一阶段建议

E 的审核步骤、F 的写作和审核步骤均有 92 分警告：自然语言证据名称或验收条目与结构化回执未逐项匹配。人工核对文件发现相关内容实际存在，但当前系统在 pilot/shadow 下允许完成。未修改历史分数，也未放宽门禁。

下一阶段应统一证据类型与验收条目的稳定标识，增加真实“审核拒绝→修订→再次审核”闭环，并在隔离部署中做运行中 worker 进程退出、网络故障和恢复演练，再验证严格门禁。当前结论为：本阶段两轮试运行交付、退回、取消、刷新与下载通过；严格生产稳定性尚不能据此宣告通过。
