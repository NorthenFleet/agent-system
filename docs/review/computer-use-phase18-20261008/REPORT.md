# 第十八阶段：草稿保存、恢复与清理

日期：2026-10-08。结论：功能已完成并发布，隔离 Computer Use 与生产刷新恢复验证通过。

## 行为

启动任务表单的标题、项目、任务类型及目标自动保存到当前浏览器 localStorage，按登录模式和用户 ID 分开存储。重新交付目标中的原任务、产物、路径、哈希和失败原因一同保留。身份尚未就绪时不保存。

整页刷新或关闭页面后重开，会提示恢复或丢弃；选择之前禁用编辑、提交及重新交付草稿覆盖。恢复不会自动创建任务，当前不可用项目不能提交，需要重新选择。用户切换时清空当前表单并检查对应账号的草稿。

提交失败保留内容，并提示先检查任务列表，避免响应不确定时重复提交。成功响应仅清理相同账号、相同内容的已提交草稿；较晚返回的成功响应不会清除另一个账号或新编辑的草稿。清理失败会提示并保留内容。支持清空当前草稿和丢弃待恢复草稿。

## 边界与后续

草稿是当前浏览器内的单账号单份草稿，不跨设备同步，清除浏览器存储会丢失。账号分键是页面恢复逻辑隔离，不是对同一浏览器本地数据的加密访问控制。同一账号同时编辑多个标签页尚无冲突合并，最后保存的版本会生效；本阶段没有声称支持多标签协作。

本阶段未新增任务创建接口的幂等机制。网络响应丢失时先核对任务列表，不能单凭“提交失败”认定后端没有创建任务。

下一阶段优先补齐重复提交与响应丢失的幂等闭环，再推进新旧交付的结构化版本关联。
