# 第八阶段：写入中断防重复执行

日期：2026-10-06。结论：本阶段修复与验证完成，整体优化尚未全部验收。

## 问题与修复

原 requeue_stale_steps 对所有租约过期步骤统一重新排队。对于已经产生写入、但尚未保存完成回执的步骤，仅有幂等键不能证明外部工具已经实现幂等，自动重试可能造成重复写入。

现在根据持久化步骤合同区分处理：只读步骤保留原接管机制；声明有副作用的步骤不自动重试，标记失败、保留未知副作用记录，并创建待审批的 verify_effect 恢复项。它只允许核实，不能授权删除或回滚。现有评估循环将任务转入等待反馈，前端展示原因与恢复项。并发保护继续采用原租约令牌和到期时间的条件更新；重复扫描不会重复生成恢复项。

没有将未知结果当作未执行，没有切换生产全局严格模式，没有改写历史任务。

## 范围与剩余工作

此次 PostgreSQL 演练为受控文件写入器和真实服务类，不是再次运行完整 OpenClaw worker；上一阶段的完整 worker 只读恢复验证继续有效。本阶段不声称所有外部工具已实现恰好一次执行。

3038 是仅本机的只读展示测试适配器，身份和计划为夹具；不会执行界面中的写操作，也没有消息发送器。本阶段没有通过浏览器批准补偿，未验证生产身份权限。前端仍使用通用“批准补偿”按钮，合同正文已明确只读核实；该文案及完整审批、核实、制定恢复方案、再审批闭环仍待下一阶段验收。

整体剩余重点：完整人工恢复闭环、长时间稳定性、生产配置下的全面验收。不能据本阶段宣布个人贾维斯已达到长期无人值守运行条件。
