# 第十九阶段：任务创建重试去重

日期：2026-10-08。结论：实现、自动化回归、真实 PostgreSQL 并发测试与 Computer Use 验证通过。本阶段没有发布到生产；生产前端仍是第十八阶段版本。

## 行为

前端在发送创建请求前生成并持久化提交标识。请求失败、响应丢失、刷新页面再恢复草稿后，原内容继续使用原标识。服务端按用户身份隔离标识，复用既有消息唯一约束和数据库事务；PostgreSQL 在检查会话及重复消息前获取事务级 advisory lock，避免并发首次提交同时创建会话或任务。

同一账号、同一标识、相同内容返回原任务；同一标识对应不同内容则拒绝。前端修改提交内容后生成新标识；主动清空或丢弃草稿后再次填写也视为新提交。旧客户端未传标识时保持原行为。

无法保存提交标识时不发送创建请求。已保存标识损坏时禁止恢复为一次新的提交，保留异常提示供用户处理。界面说明“结果尚未确认”和保留原内容重试的含义，不再一律把已保存草稿称为未提交。

## 发布状态与下一阶段

前端构建位于 /private/tmp/agent-system-phase19-dist。本阶段未更改生产静态入口，也未重启生产 API 或 worker。

发布需要前后端配套，不能只发前端：旧后端忽略新字段时无法提供去重保证。当前工作区包含其他并行功能改动；backend-release-scope.json 显示 worker 源码已不同于第十三阶段留存基线，补偿服务仍匹配。直接从当前工作区重启会扩大加载范围，不能据本阶段局部测试宣称整套变更已验收。

下一阶段：整理可复核的前后端联合候选版本，核对与生产版本的差异，先在生产副本完成发布及回退演练，再安排空闲窗口发布、验证健康和创建重试。生产任务不用于注入响应丢失故障。

## 边界

此机制保证同一用户复用同一个提交标识时的创建去重，不是按文本相似度合并任务。丢弃草稿、清空浏览器存储、换设备、修改内容、旧客户端不传标识均不能自动识别为原提交。多标签页独立生成标识仍可能创建不同任务，当前不支持跨标签协作。

本阶段不新增数据库结构，不自动清理去重记录；去重依赖原消息和任务记录保留。实验 A/B 账号入口沿用旧夹具，不作为后端身份隔离证据，身份隔离由独立服务测试验证。实验列表接口展示所有测试样本，不代替生产权限验证。
