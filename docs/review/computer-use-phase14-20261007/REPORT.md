# 第十四阶段：短时并发与交付文件变更验证

日期：2026-10-07。结论：本次限定范围通过，未发现需要修改生产逻辑的问题。新增独立测试脚本及 HTTP 下载回归测试，没有重启或改动生产服务。

## 场景与隔离

使用独立 PostgreSQL 数据库 agent_system_cu_phase14_20261007，启动 4 个独立进程运行真实 CommandCenterWorker 循环、领取租约、审批及回执校验逻辑。测试窗口约 150 秒，每隔 20 秒投放一批，共 60 个补偿案例。执行器为固定只读夹具，返回预制回执；没有调用模型，也没有实际执行文件恢复。所有文件修改仅发生于本目录下的测试样本，修改前的原文件另存保留。发送器禁止外发。

初始失败步骤、只读核实失败及恢复计划由夹具建立，每个原步骤执行次数为 1。回执损坏或资源变更在批准恢复前注入，然后由实际 worker 完成生产门禁校验。

## HTTP 下载回归

最终相关后端回归共 48 项通过（61.83 秒），包含真实子进程退出后的租约恢复测试；6 条既有弃用提示。git diff --check 通过。

新增 3 个参数化测试，使用真实 FastAPI 路由和文件读取器，身份与任务元数据通过夹具提供：先下载登记版本获得 200 及原字节，检查 no-store、nosniff 和附件响应；随后分别更改、移走文件或替换为指向目录外文件的符号链接，再下载均为 409，响应不含变更内容。未登记产物返回 404，任务读取收到当前用户 sub 的范围参数。

首次测试身份夹具误用 id 字段，导致用户范围断言失败；改为认证协议的 sub 字段后通过。初次失败记录保留在 backend-tests.txt，单项复验见 download-tests.txt，最终整组结果见 backend-tests-final.txt。此次没有修改认证逻辑或放宽断言。

## 验证边界与下一阶段

这不是 24 小时稳定性测试、吞吐量基准或生产可用性保证，也不证明外部工具的至多一次写入。固定执行器使本次能够集中检查并发领取、审批隔离和回执门禁，无法覆盖模型延迟、外部网络故障或远端恢复语义。

本阶段没有新增浏览器 Computer Use 操作或前端构建，不把此前页面验收算作此次测试。下载测试验证登记版本在之后每次读取时重新校验，不保证文件之后永久不变。生产代码未修改，无需部署。

下一阶段建议补齐用户可见的故障恢复闭环：通过 Computer Use 检查“文件验收后变更→下载失败提示→查看失败原因与原证据→明确重新提交交付”的交互，同时验证刷新和重开页面后状态一致。更长时间、真实模型及外部工具的稳定性验证仍需单独安排。
