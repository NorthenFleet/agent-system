# 第三阶段 A：受控执行内核与默认关闭的准入检查

承接已批准第三阶段“受控远程执行”，先完成可隔离验证的内核；不把前两阶段
仍未完成的七节点验收标记为通过。本次不启用生产执行入口。

## 原则与范围

- 复用 `work_runs` / `work_run_events`，不另建任务或执行账本。
- 只允许无参数 `host.info`（Linux/macOS 的 `uname -srm`），无 Shell/URL/路径输入。
- 生产保持未激活。真实执行需要正式登录、管理员身份、服务端审批授权器、独立
  SSH 凭据绑定、稳定节点身份及新鲜观测；缺一拒绝，不能借开发管理员 token 放行。
- 不发密钥，不写 authorized_keys，不启用 SSH，不修改认证策略，不接入现有 worker。
- 取消或超时只证明控制端 SSH 停止，不能推断远端已经停止；不确定结果不得自动重试。
- 可见的准入检查只有 GET 投影，不创建任务或探测远端。

## 实现与所有权

1. 后端账本：`WorkRunService.claim_at_most_once` 原子创建或返回既有回执，绑定规范化
   请求摘要；相同键不同请求冲突；已终止/过期也不新建 attempt。原 claim 重试不变。
2. 主线：封闭请求契约、静态操作目录、节点准入、独立凭据验证、限时限输出 SSH
   适配器；通过上述账本保存节点/操作/参数摘要/时间/退出码/结果。审批接口默认拒绝，
   不伪造已对接真实 Command Center 审批。
3. 前端：监控页显示受控执行准备情况和阻塞项，没有执行按钮；旧快照兼容，陈旧
   快照不显示为可执行。已有物理节点监控保持兼容。

## 验收

- 无显式启用、开发登录、无审批、无专用凭据、身份不匹配、离线、维护中、陈旧
  观测、Windows、非法操作/额外参数：执行前失败，不启动进程。
- 相同请求并发、完成后重放、过期后重放仅一次创建；不同绑定同键冲突。
- 固定 SSH argv 无 shell=True，严格主机密钥、明确 IdentityFile、禁密码/Agent/转发。
- 输出上限、超时、取消和控制端异常有有界清理及不确定回执，不猜测远端完成。
- 全部测试在隔离 SQLite/临时进程完成；Postgres 仅在独立 schema 可证明隔离后验证。
- 后端相关回归、前端测试、类型/构建、真实页面 GET 检查；生产未新增执行 API。
