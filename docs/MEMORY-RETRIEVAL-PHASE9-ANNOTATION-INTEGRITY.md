# 记忆检索第九阶段：标注完整性与证据审核

## 目标

把第八阶段生成的候选池变成可被人工可靠审核的数据工作流。重点不是自动激活更多样本，而是确保每条进入离线评测的标签都能回答四个问题：审核时看到了什么、谁做了决定、来源后来是否变化、数据集是否包含安全反例。

本阶段不替代人工判断，不批量勾选审核清单，不自动激活用例，也不自动切换线上检索策略。

## 数据模型

`memory_retrieval_eval_cases` 新增：

- `reviewer_confidence`：`unreviewed`、`medium` 或 `high`；
- `source_snapshot_hash`：人工审核时所依据的权威记忆内容哈希。

新增不可变事件表 `memory_retrieval_eval_case_events`，记录：

- 创建、编辑、激活和归档事件；
- 变更前后状态、用例版本和操作人；
- 当时的来源快照哈希与完整用例哈希。

历史用例迁移时写入 `imported` 基线事件，后续每次变更追加新事件，不覆盖旧事件。

## 激活门禁

所有用例激活前必须同时满足：

1. 问法、作用域、来源标签三项审核清单全部完成；
2. 审核置信度为 `medium` 或 `high`；
3. 自动生成用例的权威记忆仍存在且属于当前用户；
4. 当前权威记忆内容与审核快照一致；
5. 管理员通过 Element Plus 确认框显式确认激活。

如果权威记忆在审核后发生变化，服务拒绝继续以 `active` 状态保存。审核者必须先把用例保存为草稿；系统会重置审核清单和置信度，再对新内容重新审核。

## 证据审核与审计接口

```http
GET /api/v3/context/evaluations/retrieval/review-queue
GET /api/v3/context/evaluations/retrieval/cases/{case_id}/events
```

审核队列按来源返回权威记忆标题、原文、作用域、内容哈希、更新时间、候选数量、安全反例数量及漂移用例。工作台编辑弹窗直接展示这些证据和用例审计轨迹。

## 评测和切流门禁

评测协议升级为 `memory-retrieval-eval.v3`，数据集哈希纳入审核置信度和来源快照哈希。运行离线评测前会拒绝来源已经漂移的激活用例。

统一切流门禁新增：

- `source_evidence_current`：激活标签的来源证据未漂移；
- `approved_source_coverage`：每条权威记忆至少有一条激活标签；
- `safety_negative_coverage`：存在至少一条已激活的禁止来源反例。

这些检查只产生阻断原因和建议，仍不会自动切流。

## 工作台能力

- 覆盖度区域显示安全反例、来源漂移、来源缺失和审计事件数；
- 列表显示每条用例的人工审核置信度；
- 编辑时展示权威记忆原文，而不是只显示来源 ID；
- 来源变更时给出红色警告并阻止直接激活；
- 审计轨迹显示版本、事件、操作人和时间。

## 当前完成边界

第九阶段完成的是可信人工标注所需的系统能力。现有 35 条候选仍保持草稿和未审核状态，不因为迁移、测试或部署而自动成为真值。

下一步由业务审核者逐条处理候选：改写真实问法、核对作用域、补充禁止来源、选择置信度并确认激活。达到至少 30 条激活样本、覆盖全部权威记忆且包含安全反例后，才能运行 `memory-retrieval-eval.v3` 基准评测。

用于组织这30条人工审核作业的持久化批次、来源平衡策略和安全反例建议，见《记忆检索第十阶段：人工标注作业批次》。
