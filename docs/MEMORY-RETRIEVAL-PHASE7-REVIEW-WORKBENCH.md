# 记忆检索第七阶段：标注草稿与人工审核工作台

## 目标

将“已审核长期记忆”转换为可人工校正的检索评测草稿，并提供统一的管理员工作台，完成从样本准备、人工审核、离线评测到切流建议的可观测闭环。

本阶段不改变线上检索结果，不自动激活草稿，也不自动切换检索策略。

## 数据流

```text
已审核长期记忆
        │
        ├─ 使用向量投影相同的权威记忆选择器
        │
        ▼
评测草稿（draft）
        │  人工改写真实业务问法、校验作用域和来源
        ▼
已激活标注（active）
        │
        ├─ Baseline / weighted-rrf.v1 离线对比
        └─ 与在线 Shadow 指标合并
        ▼
切流建议（仅建议，不自动执行）
```

## 草稿生成

```http
POST /api/v3/context/evaluations/retrieval/cases/generate-drafts
```

生成器具有以下约束：

- 仅读取当前管理员所属用户的已审核权威记忆；
- 第七阶段使用 `source_memory_ref` 幂等生成标准草稿；第八阶段已将唯一约束扩展为 `source_memory_ref + variant_key`，以支持多问法；
- 自动写入的 `origin` 为 `approved_memory_draft`；
- 期望来源默认指向生成草稿的权威记忆；
- 状态始终为 `draft`，返回值 `automatic_activation=false`；
- 生成问法只是审核起点，不被当作生产真值。

## 审核工作台

管理员菜单新增“记忆评测”，路由为 `/memory-evaluation`。页面集成：

- 在线 Shadow 样本数、可用率、延迟和排序变化；
- 已激活标注数与统一切流门禁的阻断原因；
- 草稿、已激活、已归档用例的筛选和编辑；
- 从权威记忆幂等生成草稿；
- 运行离线评测并展示最新结果。

激活、归档和运行离线评测都需要明确的 Element Plus 确认交互。取消确认时不调用后端，不产生未处理 Promise 异常。

## 权限和安全边界

- 后端评测与向量运维路由映射到 `memory-evaluation` 模块；
- 评测用例管理和草稿生成仍只允许 `admin` 角色；
- 草稿按 `owner_user_id` 隔离，不会把其他用户的记忆生成为本用户标注；
- 只有 `active` 用例进入数据集哈希和切流门禁；
- 无论门禁是否通过，`automatic_switch_performed` 始终为 `false`。

## 运行手册

1. 管理员点击“从权威记忆生成草稿”。
2. 对每条草稿改写成真实用户可能输入的业务问法。
3. 核对被测用户、项目、智能体和 Top-K。
4. 校验期望来源，并补充跨用户、已归档、过期或冲突的禁止来源。
5. 确认后激活；不确定的样本保持草稿或归档。
6. 达到最低激活样本数后运行离线评测。
7. 只在统一门禁显示 `READY` 后，再单独审批是否切流。

## 验证基线

- 草稿生成器要求幂等，且永不自动激活；
- 接口测试覆盖已审核记忆到草稿的端到端转换；
- 页面测试覆盖阻断门禁、草稿展示和生成操作；
- 前端需通过 `vue-tsc` 和生产构建；
- 每次变更后重跑记忆检索、Shadow、向量和统一门禁回归测试。

## 下一阶段入口

下一阶段不是扩大自动化范围，而是建立可信的标注数据集：逐条审核草稿，补充真实业务问法的同义表达、跨用户隔离反例与已归档记忆反例，直到至少 30 条激活用例。

该阶段已在 `MEMORY-RETRIEVAL-PHASE8-TRUSTED-DATASET.md` 实现数据结构、幂等变体生成、覆盖度观测和不可绕过的人工审核门禁。
